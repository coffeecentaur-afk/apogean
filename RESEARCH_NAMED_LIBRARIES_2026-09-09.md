## Fit and risks for Apogean

**WombatQOL — optional gameplay/content dependency, weak fit for shared infrastructure.** Source confirms server-side gameplay/worldgen options and client-side visual options, many defaulting on. Its water-style hook substitutes its own `VileWater` when `Main.bgStyle == 1` and the option is enabled. This is a concrete overlap to consider for Apogean’s owned water/biome appearance, not a demonstrated conflict. Toggling features does not turn the package into an art-authoring library. No reuse license was visible in the inspected repository tree; public source/assets should not be treated as an established reuse grant. [Configuration](https://github.com/lazy-wombat/WombatQOL/blob/45c06087f9562c3c0e592e048f59b4f937eff493/Config.cs), [water hook](https://github.com/lazy-wombat/WombatQOL/blob/45c06087f9562c3c0e592e048f59b4f937eff493/WombatQOL.cs), [repository tree](https://github.com/lazy-wombat/WombatQOL/tree/45c06087f9562c3c0e592e048f59b4f937eff493).

**ModLiquid — strongest named candidate for real portable acid, with substantial integration risk.** Static review found:

- **Damage and owned liquid art:** `OnPlayerCollision` and `OnNPCCollision` are documented extension points for damage/debuffs. Texture, block/slope textures, drawing, lighting, animation, and waterfall hooks let Apogean supply its own liquid appearance. Acid damage rules, immunities, and multiplayer authority still require implementation. This is liquid rendering infrastructure, not a complete biome-art system. [Pinned API](https://github.com/Lion8cake/ModLiquidLib/blob/282498893150b53d2e52efe26be0813aa8c8e193/ModLoader/ModLiquid.cs)
- **Portability:** the author’s example registers a bucket item through `CreateLiquidBucketItem`, implements pouring and empty-bucket return, and calls `NetMessage.sendWater` for client placement. This demonstrates source-level support, not a tested acid bucket. [Example bucket](https://github.com/Lion8cake/ModLiquidExampleMod/blob/983cf0491f0c3543d2b4e0c53da1b1369cecd796/Content/Items/ExampleLiquidBucket.cs)
- **Mixing:** `LiquidMerge` selects a resulting tile and defaults to stone. `PreLiquidMerge` can suppress that behavior; its documentation specifies server execution in multiplayer. The author’s custom example converts colliding liquids into another liquid and explicitly synchronizes changes. Arbitrary acid dilution/neutralization, volume rules, and reactions with water/lava/honey/shimmer are therefore custom work, not supplied chemistry. [API](https://github.com/Lion8cake/ModLiquidLib/blob/282498893150b53d2e52efe26be0813aa8c8e193/ModLoader/ModLiquid.cs), [custom merge example](https://github.com/Lion8cake/ModLiquidExampleMod/blob/983cf0491f0c3543d2b4e0c53da1b1369cecd796/Content/Liquids/ExampleCustomMergeLiquid.cs)

Reliability qualifications: the author warns of extensive changes to liquid handling and possible conflicts with other liquid mods. Source includes world persistence, tile-network serialization edits, and many IL/On hooks, making exact tML/modpack testing necessary. Open tracker reports concern frozen waterfalls, retained references after unloading, and NPC movement; these are **reporter claims, not reproduced findings**. [Save code](https://github.com/Lion8cake/ModLiquidLib/blob/282498893150b53d2e52efe26be0813aa8c8e193/IO/LiquidIO.cs), [network edits](https://github.com/Lion8cake/ModLiquidLib/blob/282498893150b53d2e52efe26be0813aa8c8e193/Hooks/NetMessageHooks.cs), [hook registration](https://github.com/Lion8cake/ModLiquidLib/blob/282498893150b53d2e52efe26be0813aa8c8e193/ModLiquidLib.cs), [#10](https://github.com/Lion8cake/ModLiquidLib/issues/10), [#11](https://github.com/Lion8cake/ModLiquidLib/issues/11), [#12](https://github.com/Lion8cake/ModLiquidLib/issues/12).

The author anticipates native integration for 1.4.5 and eventual library legacy status. That is a plan: linked **PR #4899 remains open and unmerged** at lookup (currently non-draft, base branch `1.4.4`). Do not assume native availability or a migration date. Library source carries **MIT**, copyright 2026 Lion8cake, with notice-retention terms. [Author FAQ](https://steamcommunity.com/sharedfiles/filedetails/?id=3539368598&l=english), [upstream PR](https://github.com/tModLoader/tModLoader/pull/4899), [license](https://github.com/Lion8cake/ModLiquidLib/blob/282498893150b53d2e52efe26be0813aa8c8e193/LICENSE.md).

**SerousCommonLib — plausible shared-utility dependency, not an acid or biome-content solution.** Author-advertised features include UI controls/layout, text input, tooltip/loot/tile-scanning helpers, reflection, and IL/On helpers. Text input explicitly lacks chat-tag handling. Source also patches UI recalculation and tile nearby-effects, so library classification does not imply zero runtime interaction. The author’s August 11 Workshop reply reports WebCom fixed its side of an incompatibility and notes limited maintenance time; it does not establish universal resolution. [Author feature list/reply](https://steamcommunity.com/sharedfiles/filedetails/?id=2908170107&l=english), [UI patch](https://github.com/absoluteAquarian/SerousCommonLib/blob/84078461883c9d6d9757b335364b1d9b0da51bbf/src/API/Edits/ClippedListRecalculateSupport.cs), [tile hook](https://github.com/absoluteAquarian/SerousCommonLib/blob/84078461883c9d6d9757b335364b1d9b0da51bbf/src/API/Edits/NearbyEffectsBlocking.cs). The license is **MIT**, although its copyright line still contains `[year] [fullname]` placeholders. [License](https://github.com/absoluteAquarian/SerousCommonLib/blob/84078461883c9d6d9757b335364b1d9b0da51bbf/LICENSE.txt).

## Research recommendation — no adoption or tests performed

Apogean-specific addition after integration review: the later acid fixture must exercise Terraria's native capture-camera liquid drawing as well as ordinary play, different lighting modes and waterfalls. The user's earlier DrawLiquid crash makes that a retained regression case; no claim that this library caused or fixes the previous crash.

Prioritize ModLiquid for a later isolated acid feasibility check; consider Serous only for specific utilities that justify a runtime dependency. Keep WombatQOL an explicit gameplay/content choice, and keep Wombat’s Combat unresolved. Before any adoption, evidence is still needed on the exact installed tML build for loading, bucket pickup/pouring, directional mixing and volume behavior, player/NPC damage, dedicated-server synchronization, save/reload and missing-mod handling, plus owned liquid art under different lighting modes and waterfalls. Nothing in this report certifies compatibility or authorizes those tests. StructureHelper, SubworldLibrary, Luminance, and internal tools were outside this sidecar’s scope.
