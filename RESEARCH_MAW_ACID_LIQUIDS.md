# Wayfinder Issue 22 — Maw Acid Pools and Custom-Liquid Limits

> **Decision superseded 2026-09-01.** The technical liquid-limit findings remain valid, but Apogee no longer approves fake acid tiles for normal world generation. `WORLD_PLACEMENT_ATLAS.md` reserves dry digestive-basin geometry and permits a later real-water prototype only if it can remain local; acid is not required for Environmental Alpha or progression.

## Scope and evidence baseline

**Proven — version audited.** This report is tied to the locally installed stable build `tModLoader 2026.07.3.0`, product version `1.4.4.9+2026.07.3.0`, commit `666f69962d3bdffde54fc14025f02634965b4e7c`. The audit used the installed `tModLoader.dll` and `tModLoader.xml`, the official ExampleMod at that exact commit, and the corresponding Terraria/tModLoader source patches. Links below are pinned to that commit rather than to a moving branch.

**Recommendation — decision.** Implement localized yellow Maw stomach acid as an animated, non-solid custom tile pool with custom overlap detection and a player damage-over-time debuff. Do **not** represent it as a fifth liquid, biome-styled water, lava, honey, or shimmer. Dormancy should change only animation, color, particles, and emitted light; it must not change the damage predicate. This is the smallest implementation that is persistent, multiplayer-safe, locally identifiable, visually controllable, and unable to recolor unrelated water.

## Exact liquid support boundary

**Proven — arbitrary physical liquids are unsupported.** The public physical-liquid registry contains exactly four IDs: water `0`, lava `1`, honey `2`, and shimmer `3`; `LiquidID.Count` is `4`. There is no `ModLiquid`, `LiquidLoader`, or registration API in this build. Renderer physics arrays are sized from `LiquidID.Count`, and NPC wet-gravity tables likewise describe exactly the four vanilla states. ([LiquidID](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/ID/LiquidID.cs.patch), [LiquidRenderer patch](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/GameContent/Liquid/LiquidRenderer.cs.patch), [NPC liquid multipliers](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/NPC.TML.cs#L245-L255))

**Proven — the six-bit tile field is not an extension API.** `LiquidData` reserves six packed bits for `LiquidType`, so values `0–63` fit in memory, but supported semantics still stop at IDs `0–3`. The exact world serializer encodes only water/lava/honey/shimmer flags; an unknown value does not have a persistent world-file identity and is read back as a vanilla type. The network tile messages can carry a raw type byte, but that does not fix world persistence, renderer array bounds, collision flags, mixing rules, buckets, or other four-type switches. Writing `LiquidType > 3` is therefore unsupported and can cause incorrect behavior or faults. ([tile data layout](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/TileData.Default.cs#L33-L44), [public tile liquid properties](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/Tile.TML.cs#L168-L185), exact installed assembly: `Terraria.IO.WorldFile.SaveWorldTiles`, `LoadWorldTiles`, `Terraria.NetMessage`, and `Terraria.MessageBuffer`)

## What water-style APIs actually do

**Proven — `ModWaterStyle` is a client-side drawing style.** Its own documentation says it “represents a style of water that gets drawn,” and the type is client-autoloaded. It registers normal, block, and slope textures and exposes only:

- `ChooseWaterfallStyle`: selects a waterfall drawing style.
- `GetSplashDust`: selects splash dust.
- `GetDropletGore`: selects falling-droplet gore.
- `LightColorMultiplier`: multiplies light seen **behind** styled water; it does not emit light or alter gameplay.
- `BiomeHairColor`: supplies the biome hair-dye color only.
- `GetRainTexture` / `GetRainVariant`: change rain visuals.

It has no hook for damage, flow, collision, drowning, fishing, buckets, pumps, settling, mixing, serialization, or per-tile chemistry. ([`ModWaterStyle`](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/ModLoader/ModWaterStyle.cs#L9-L96), [official ExampleWaterStyle](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/ExampleMod/Content/Biomes/ExampleWaterStyle.cs))

**Proven — `ModWaterfallStyle` is also client-side and visual.** It supplies a waterfall texture plus `AddLight(i,j)` and a draw `ColorMultiplier`. It cannot create a physical fall, damage an entity, or change the liquid carried by that fall. ([`ModWaterfallStyle`](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/ModLoader/ModWaterStyle.cs#L98-L137), [official ExampleWaterfallStyle](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/ExampleMod/Content/Biomes/ExampleWaterfallStyle.cs))

**Proven — `ModBiome.WaterStyle` is one player-local scene choice, not tile metadata.** A biome inherits `ModSceneEffect.WaterStyle`. Active scene effects are sorted by priority and weight; the first qualifying non-null water style becomes `Player.CurrentSceneEffect.waterStyle`, and `WaterStylesLoader` reads it from `Main.LocalPlayer`. In the renderer, only physical water type `0` is replaced by the selected style; honey remains a fixed style and lava/shimmer retain their own paths. Consequently, every visible ordinary-water tile using the selected scene style can be recolored, including unrelated wells, player-built pools, and water moved into the biome. Overlapping biomes do not compose styles: one winner is selected by scene priority/weight. ([`ModSceneEffect.WaterStyle`](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/ModLoader/ModSceneEffect.cs#L16-L20), [scene selection](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/ModLoader/SceneEffectLoader.cs#L65-L147), [`WaterStylesLoader`](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/ModLoader/WaterStyleLoader.cs#L20-L96), [renderer water substitution](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/Main.cs.patch#L6521-L6595))

**Proven — generic drawing hooks can imitate a liquid but cannot add liquid semantics.** `ModTile`/`ModBlockType` support global and per-tile animation, `PreDraw`, `PostDraw`, registered `SpecialDraw`, particles, and `ModifyLight`; `ModSystem.PostDrawTiles` can draw a client-only tile overlay. These are supported ways to render an animated pool surface, body, glow, bubbles, and edges. They do not make the pixels flow, settle, collide, drown, fish, bucket, pump, or synchronize as liquid. `IsTileDangerous` only marks a tile for danger-sense visuals; it does not apply damage. ([tile animation and special drawing](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/ModLoader/ModTile.cs#L314-L448), [block draw and light hooks](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/ModLoader/ModBlockType.cs#L120-L177), [`PostDrawTiles`](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/ModLoader/ModSystem.cs#L305-L309))

## Immersion identification

**Proven — vanilla wet flags identify physical liquid, not its water style.** `Entity.wet` means the entity overlaps physical liquid; `lavaWet`, `honeyWet`, and `shimmerWet` distinguish the other three states. `Collision.WetCollision` scans liquid-filled tiles and reports wet/honey/shimmer; `Collision.LavaCollision` is separate. `Collision.DrownCollision` tests head-area overlap with non-lava, non-shimmer liquid. None reads `ModWaterStyle`, scene priority, or biome identity. ([entity wet documentation](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/Entity.cs.patch#L61-L68), exact installed assembly: `Terraria.Collision.WetCollision`, `LavaCollision`, and `DrownCollision`)

**Inference — styled-water detection is only approximate for a player.** `player.wet && !player.lavaWet && !player.honeyWet && !player.shimmerWet && player.InModBiome<MawBiome>()` means “the player is in ordinary water while the Maw biome predicate is active.” It does **not** prove that the particular water tile is an acid pool, and an overlapping higher-priority scene can visually select a different style. `Player.InModBiome<T>()` is the supported biome query, but style selection remains scene-level. ([`ModBiome` guidance](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/ModLoader/ModBiome.cs#L8-L20))

**Proven — NPCs and projectiles have no authoritative “in this water style” query.** They have physical wet flags, but water style is resolved from `Main.LocalPlayer.CurrentSceneEffect`, which is inappropriate for server gameplay and can differ between clients. A mod must combine a physical-liquid tile scan with its own coordinate/biome classifier, or—in the recommended design—scan for exact Maw acid tile types intersecting the entity hitbox. Projectiles with `ignoreWater` also bypass normal wet movement behavior, which further separates projectile wetness from scene styling. ([entity wet documentation](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/Entity.cs.patch#L61-L68), [`WaterStylesLoader` local-player selection](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/ModLoader/WaterStyleLoader.cs#L36-L45))

## Consequences of using real water

**Proven — fishing.** Biome-styled water remains ordinary water. Fishing classifies lava and honey explicitly and treats neither as water; ExampleMod then checks the player's biome separately. A water style does not create an acid fishing category or alter pond validation. ([official fishing example](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/ExampleMod/Common/Players/ExampleFishingPlayer.cs#L27-L44), [fishing hooks](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/ModLoader/ModPlayer.cs#L1049-L1070))

**Proven — pumps, buckets, mixing, and settling.** Vanilla pumps transfer liquid amount and the fixed liquid type. Buckets place or collect only the four fixed IDs. Liquid settling flows same-type liquid and invokes hard-coded water/lava/honey/shimmer merge outcomes for different types. A water style does not accompany moved water and cannot preserve “acid provenance.” (Exact installed assembly: `Terraria.Wiring.XferWater`, `Terraria.Player.ItemCheck_UseBuckets`, `Terraria.Liquid.Update`, `LiquidCheck`, and `GetLiquidMergeTypes`; tile network guidance: [`NetMessage.SendTileSquare`](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/NetMessage.cs.patch#L613-L619))

**Proven — world generation and multiplayer.** Worldgen can place any of the four physical liquids by setting tile amount/type and settling them, but cannot register a fifth type. Vanilla liquid tile state is world-saved and network-synchronized; a mod water style is client content selected independently for each player's current scene. Damage keyed only to a style/biome would therefore affect unrelated type-0 water and can disagree around biome boundaries or overlaps.

**Proven — collision and drowning.** Styled type-0 water retains normal swimming, wet movement, water walking, projectile wet behavior, splash behavior, and drowning. `ModWaterStyle` cannot replace any of them. A visual acid overlay over actual water also retains all of those systems underneath.

**Inference — damaging biome-styled water is technically possible but not safely localizable.** A `ModPlayer` can damage a player whenever the approximate player predicate above is true, using the supported bad-life-regeneration hook. It is unsafe for Maw acid because all ordinary water in the active biome becomes damaging, pumped water loses intended origin, and scene overlap/boundary behavior is ambiguous. The client-only `ModWaterStyle` itself must never be the authority for damage. [`UpdateBadLifeRegen` is the supported damage-over-time hook and is called on local, server, and remote clients](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/ModLoader/ModPlayer.cs#L192-L198); [ExampleMod demonstrates the exact life-regeneration pattern](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/ExampleMod/Content/Buffs/ExampleLifeRegenDebuff.cs#L24-L47).

## Alternatives considered

| Alternative | Supported behavior | Decision |
|---|---|---|
| Actual water + `ModWaterStyle` | Flows, settles, fishes, pumps, buckets, swims, and drowns as water; scene-wide visual replacement | Reject: cannot identify individual acid pools and recolors unrelated water. |
| Actual water + custom draw overlay | Can add localized yellow visuals if the mod tracks coordinates | Reject: underlying water still moves independently; provenance, pumps, buckets, and biome overlap remain fragile. |
| Reuse lava | Provides damage, lava immunity, flow, mixing, buckets, lava fishing, item destruction, and lava collision | Reject: inherits every lava semantic and cannot be restyled through `ModWaterStyle`; broad compatibility cost. |
| Reuse shimmer | Provides shimmer collision, player phasing, item/NPC transformations, and fixed rendering | Reject: destructive, progression-sensitive behavior unrelated to acid. |
| Reuse honey | Provides honey viscosity, wet flags, honey buff/fishing/buckets | Reject: wrong mechanics and still not a distinct chemistry. |
| Custom projectiles | Good for temporary splashes, falling globs, spit, or short-lived puddles | Keep as a secondary effect only; unsuitable for persistent worldgen pools because of lifetime, projectile limits, and network churn. |
| Animated non-solid custom tiles | Persistent tile state, exact local identity, normal tile sync, custom animation/draw/light, custom hitbox damage | **Select.** The missing liquid semantics are deliberate and testable rather than accidental. |

## Finite recommended implementation

**Recommendation — representation.** Add one `MawAcidPoolTile` family whose connected frames provide surface, body, left/right edge, corner, and bottom variants. It is active, non-solid, non-platform, frame-important only if the chosen framing requires it, immune to lava/water destruction, drops no item, and is not a water/honey/lava/shimmer source. Generate shallow authored basins with acid tiles in otherwise empty cells and ordinary solid Maw terrain around/below them. Use `AnimateTile`/`AnimateIndividualTile` for slow surface contraction and `PostDraw` or registered `SpecialDraw` for bubbles and a restrained highlight. Use `ModifyLight` for yellow terrain light.

**Recommendation — local detection.** Use one shared allocation-free helper that converts an entity hitbox to clamped tile bounds and tests rectangle intersection against active `MawAcidPoolTile` cells. Do not use `Player.wet`, `Main.waterStyle`, `CurrentSceneEffect`, or `InModBiome` as the acid predicate. The same helper can identify player, NPC, or projectile overlap if later mechanics require it.

**Recommendation — player damage.** Each update, set a reset-every-tick `inMawAcid` flag from the exact tile-overlap helper and refresh a short non-saving `Caustic Digestion` debuff while true. In `UpdateBadLifeRegen`, if the flag/debuff is active: zero positive life regeneration, set `lifeRegenTime` to `0`, and subtract `24` from `lifeRegen` for an initial **12 HP/second** defense-ignoring hazard. Keep that constant in one named balance field. This follows the official multiplayer-aware damage-over-time pattern and avoids repeated direct `Player.Hurt` packets or client-only style authority. Maw-native enemies are exempt in version one by applying no acid NPC damage at all; if non-Maw NPC damage is later desired, add a server-authoritative `GlobalNPC.UpdateLifeRegen` path guarded by an explicit `IsMawNative` classification.

**Recommendation — dormancy.** Store one world-level Maw dormancy flag with `ModSystem.SaveWorldData`/`LoadWorldData` and synchronize it with `NetSend`/`NetReceive`. Active and dormant acid use the same overlap and damage code. Dormancy changes only render parameters: reduce light output to roughly 30–40%, slow animation, lower particle frequency, and shift bright yellow toward dull amber. This makes the biome visibly asleep while preserving the stated chemical danger. ([world save and net hooks](https://github.com/tModLoader/tModLoader/blob/666f69962d3bdffde54fc14025f02634965b4e7c/patches/tModLoader/Terraria/ModLoader/ModSystem.cs#L322-L377))

**Recommendation — explicit gameplay contract.** Maw acid tiles do not flow, settle, mix, pump, bucket, count for fishing, set `wet`, support swimming/water-walking, or cause drowning. Worldgen places their exact geometry; later cleansing replaces/removes tiles explicitly. Vanilla liquid poured into the same non-solid tile cell remains a separate vanilla liquid and may add its own wet/drowning/fishing behavior, but it does not remove acid damage or change acid visuals. Treat that coexistence as an edge case, not chemical mixing, and test it. This contract avoids global hooks and is compatible with other mods because it owns only Apogean tile types and Apogean player state.

## Hazards

1. **Proven — never assign `Tile.LiquidType > 3`.** It is not persistently encoded as a new type and can reach four-entry engine arrays.
2. **Proven — never use `ModWaterStyle` or `Main.LocalPlayer.CurrentSceneEffect` as damage authority.** Both are client-side scene presentation.
3. **Inference — biome-gated `player.wet` damage will produce false positives.** Player-built and pumped ordinary water inside the Maw would become acid.
4. **Recommendation — clamp every hitbox-to-tile scan to world bounds and avoid per-tick allocations.** Players, NPCs, and projectiles can touch edge coordinates and these checks run frequently.
5. **Recommendation — keep dormancy out of the hazard predicate.** A shared visual/damage multiplier would accidentally make dormant acid safe.
6. **Recommendation — do not scan the whole world for acid each tick.** Check only entity-overlapped cells; use ordinary tile persistence and worldgen placement.
7. **Inference — vanilla liquid can coexist with a non-solid acid tile.** This is safe if defined as layered behavior, but visuals and drowning must be tested; do not silently delete other mods' or players' liquids globally.
8. **Recommendation — keep version-one acid player-only.** Broad NPC/projectile damage introduces ownership, immunity taxonomy, and network side effects that are unnecessary for the stated requirement.

## Required test matrix

| Area | Test | Expected result |
|---|---|---|
| Single player | Enter, stand in, jump through, and leave a 1-, 2-, and 3-tile-deep acid pool | Debuff starts only on tile overlap, deals 12 HP/s, stops promptly after exit, and never depends on biome activation. |
| Dormancy | Toggle active/dormant while immersed | Color/light/animation dim; damage rate remains exactly unchanged. |
| Native immunity | Spawn every Maw-native enemy in acid | No acid damage or forced wet behavior. |
| Locality | Place ordinary water beside and elsewhere inside the Maw | Ordinary water is not recolored yellow and causes no acid debuff. |
| Biome overlap | Test at Maw/forest, Maw/evil, Maw/underworld, and another mod-biome boundary | Acid tile visual/damage remains local and stable regardless of selected scene water style. |
| Vanilla liquid overlap | Pour water, lava, honey, and shimmer onto/through acid cells | No crash or tile corruption; acid remains dangerous; each vanilla liquid retains only its own vanilla semantics. Record visual layering defects. |
| Pumps/buckets | Aim pumps and every vanilla bucket at an acid basin | Acid tiles are neither moved nor collected. Any coexisting vanilla liquid behaves as vanilla liquid only. |
| Fishing | Cast into a pool made only of acid tiles, then into acid tiles containing added water | Acid-only pool is not a fishing pond; deliberately added water is judged by vanilla water rules and does not alter acid damage. |
| Collision/drowning | Use water walking, flippers, gills, lava immunity, and drowning accessories | Acid alone sets no wet/drowning/swimming state; none grants acid immunity unless Apogean explicitly adds it later. |
| Multiplayer host/client | Two players enter/leave the same pool; toggle dormancy; reconnect and late-join | Damage agrees on both peers, dormancy visual agrees after sync, and no duplicate damage or stale debuff occurs. |
| Save/reload | Save active and dormant worlds with pools near section boundaries; reload | Acid tiles, frames, and dormancy persist exactly; no tile becomes vanilla liquid. |
| Performance | Profile a dense pool while several players and many NPCs/projectiles cross it | Entity-local tile scans allocate nothing and do not scan outside each hitbox. |
| Dedicated server | Run without graphics assets loaded server-side | No reference to client-only water styles/draw state occurs in hazard logic; server remains stable. |

## Resolution

**Recommendation — issue 22 is resolved for implementation planning.** Stable tModLoader does not support arbitrary custom physical liquids. `ModWaterStyle` is appropriate only for scene-wide ordinary-water presentation and would violate the requirement not to recolor unrelated water. The approved implementation is a persistent animated non-solid Maw acid tile, exact tile-hitbox detection, supported bad-life-regeneration damage to players only, explicit Maw-native immunity by omission of NPC damage, and a synchronized dormancy state that dims visuals without changing chemistry.
